## Contracts: advance_pool and teurc

- 2026-10-25: **`open_line` takes the `Note` by value** (`PoolInterface::open_line(env, note: Note)`): Soroban forbids contract re-entry, so the pool cannot call `cpcv_note.get` while `cpcv_note.mint` is running (spec §7.2 step 10 / §7.3 deviation, orchestrator decision). The pool authenticates with `note_contract.require_auth()` (cpcv_note is the direct invoker) and checks the split; `settle` still reads the note with `NoteClient::get` (no re-entry there). `cpcv_note.set_status` must not call back into the pool.
- 2026-10-25: **Rounding surplus goes to junior**: debts round up (§5.2), so a draw or repayment can move the book debt a few stroops more than the cash that changed hands. `Pool::book_rounding` credits that surplus (always ≥ 0) to `junior_assets`, so the §5.3 invariant holds exactly (tested with zero tolerance) instead of accumulating dust. Example: the §5.6 settlement adds €7,500 + 1 stroop to junior.
- 2026-10-25: `write_off` charges the tranches exactly the decrease in `total_debt` (junior, then senior, then — only if both are exhausted — unclaimed fees); `DebtWrittenOff.amount` is the carried debt as displayed (rounded up), so `junior_loss + senior_loss` can be ≤ 1 stroop below it.
- 2026-10-25: A settlement **shortfall** (line debt > agent's half) becomes carried debt and starts the grace period if none is running (the spec only sets a deadline in `cancel`); carried debt therefore always has a deadline and can be written off. `cancel` and `settle` clear the deadline once carried debt reaches 0.
- 2026-10-25: Partial repayments (carried debt from the card balance or a later settlement, settlement shortfalls) pay interest first, then principal; the scaled debt removed rounds down (never clears more debt than paid).
- 2026-10-25: `card_draw` checks, in order: duplicate `auth_ref` (`DuplicateDraw`, before the card checks; failed draws don't consume the ref), `CardNotEnabled`, then for the credit part `AgentBlocked`, `InsufficientCredit`, `InsufficientLiquidity`, `LeverageCapExceeded`. Used refs are persistent entries (~90-day TTL).
- 2026-10-25: `NoteCancelled.debt_carried` = the line debt moved into carried debt (before the card-balance repayment); `grace_deadline` is the agent's deadline after the operation.
- 2026-10-25: `PoolStats`: `utilization_bps = total_debt / (total_debt + lendable)`; `share_price_scaled = (senior_assets + 1) × SCALE / (supply + 1)` (same virtual offsets as the conversions); `leverage_x100 = total_debt × 100 / junior_assets` (u32::MAX if junior is 0 with debt outstanding).
- 2026-10-25: eaSR uses OpenZeppelin's `TotalSupply` contract type (`Base` balances + supply counter) so SEP-41 `burn` keeps the vault supply right; the vault math is ours (§5.5). SEP-56 semantics follow OpenZeppelin: `operator` authorizes; if `operator != from` it spends `from`'s tEURC allowance, if `operator != owner` it spends `owner`'s eaSR allowance; `max_deposit`/`max_mint` = i128::MAX; `deposit`/`withdraw` events reuse `stellar_tokens::vault` (OpenZeppelin SEP-56 layout). Vault views return `Result<i128, Error>` (overflow → `Error::Overflow`); the on-chain value is the same i128.
- 2026-10-25: No new error variants. Constructor param validation (`protocol_fee_bps` and `ltv_bps` ≤ 10,000, `max_leverage` ≥ 1), `advance_clock(0)`, amounts ≤ 0 and amounts above the caller's position (`withdraw`, `redeem`, `withdraw_balance`, `junior_withdraw` > junior, `claim_fees` > fees) fail with `InvalidAmount`; amounts above lendable / pool cash fail with `InsufficientLiquidity`.
- 2026-10-25: TTLs: instance extended to ~30 days (threshold 15) on every call, views and SEP-41 methods included (OpenZeppelin leaves instance TTL to the implementor); persistent records (lines, agents, draw refs, eaSR and tEURC balances) to ~90 days (threshold 45).
- 2026-10-25: teurc keeps a plain stored admin (`admin.require_auth()` on `mint`) instead of OpenZeppelin Ownable (no ownership-transfer surface needed); its errors use the shared numbering (`InvalidAmount` for ≤ 0 and for faucet amounts above 25,000 tEURC). Unused `stellar-access`/`stellar-macros` deps were dropped from teurc and advance_pool; advance_pool tests use teurc as a dev-dependency.
- 2026-10-25: `set_blocked` emits no event (none listed in the spec).
- 2026-10-25: **End-to-end tests** live in the test-only workspace member `contracts/integration_tests` (rlib, so `stellar contract build` skips it): the three real contracts deployed and wired per §7.4 in one Env, driven with the real fixture proofs, the §5.3 invariant checked after every step exactly as the pool's tests do, plus a check that the registry and the pool's lines/positions agree. Each scenario runs twice: `native` (contract crates as rlibs) and `wasm` (the optimized `target/wasm32v1-none/release/*.wasm` registered from bytes at runtime rather than `contractimport!`, so `cargo test --workspace` needs no prior wasm build; `#[ignore]`d — run `stellar contract build` then `cargo test -p integration_tests -- --ignored`). No contract changes were needed.
- 2026-10-25: The E2E tests use **strict authorization** (never `mock_all_auths`), so cross-contract calls must pass on invoker auth (`open_line` from `cpcv_note.mint`, `set_status` from `settle`/`cancel`) and each call's required auths are asserted exactly. What each role signs: `mint`, `card_draw`, `cancel`, `write_off` = operator only; `settle` = operator (`settle`) + treasury (`settle` → `teurc.transfer(treasury, pool, total_commission)`); `junior_deposit` and SEP-56 `deposit` include the tEURC transfer as a sub-invocation; `redeem`/`withdraw`, `claim_fees`, `junior_withdraw` need no sub-invocation (the pool pays); `enable_card`, `withdraw_balance` = the agent. Test signatures expire after 120 ledgers: `Env::mock_auths` uses the max TTL, which bills a year of rent for each auth nonce and inflates fee estimates.
- 2026-10-25: Measured costs (optimized wasm, all contracts in the VM, vs live testnet protocol-29 limits = the SDK's mainnet snapshot): `card_draw` 3.2M instructions, `settle` 4.3M, `cancel` 2.8M, `write_off` 1.7M (≤ 1.1% of 400M, ≤ 7% of memory). The fee estimate of `card_draw` is ~0.41 XLM, almost all rent of the 90-day `Draw(auth_ref)` entry (SDK rent rate, an overestimate); fine on testnet. Contract sizes: teurc 10,539 B, cpcv_note 23,268 B, advance_pool 56,555 B (limit 131,072).

## ZK circuit and cpcv_note

- 2026-10-25: **`advance_pool.open_line` takes the note by value** (`fn open_line(env, note: Note)`), not `note_id` (deviation from spec §7.2 step 10 / §7.3). Soroban prohibits contract re-entry (soroban-env-host 28 calls every external contract with `ContractReentryMode::Prohibited` → "Contract re-entry is not allowed"), so `cpcv_note.mint → advance_pool.open_line → cpcv_note.get` would trap. `mint` passes the stored `Note`; the pool authenticates with `note_contract.require_auth()` (satisfied because `cpcv_note` is the direct invoker). Agreed with the orchestrator and the pool workstream.
- 2026-10-25: **G2 byte order** (spec §8.5 "do not guess"): soroban-sdk 28 `Bn254G2Affine` uses the Ethereum EIP-197 encoding `be(x.c1) ‖ be(x.c0) ‖ be(y.c1) ‖ be(y.c0)` (imaginary part first); soroban-env-host 28 decodes it by reversing each 64-byte Fp2 into arkworks' little-endian `c0 ‖ c1`. snarkjs JSON lists `[c0, c1]`, so `lib/zk/format.ts` swaps the halves. Confirmed by the Rust test verifying real snarkjs proofs, and by `vk.gamma` encoding to the well-known EIP-197 G2 generator bytes (`198e9393…`).
- 2026-10-25: Trusted setup is a **local single-contributor ceremony** (`powersoftau new bn128 15` + one contribution, `groth16 setup` + one `zkey contribute`, random entropy from `/dev/urandom`, `zkey verify`): fine for a testnet demo, but whoever ran `build.sh` could forge proofs if they kept the entropy. Every `pnpm circuits:build` is a new setup: commit the new `apps/web/zk/*` + fixture and redeploy `cpcv_note` with the new `verification_key.soroban.json`.
- 2026-10-25: `property_hash` = `Poseidon(len_bytes, chunk_0 … chunk_7)` in **one 9-input call**: circomlib/circomlibjs Poseidon takes up to 16 inputs, so arity does not require the two-call split. Normalization adds Unicode **NFC** before lowercasing (Portuguese addresses may arrive composed or decomposed); chunks are 31-byte big-endian integers, the last one zero-padded on the right; addresses over 248 UTF-8 bytes are rejected.
- 2026-10-25: The verifier rejects **non-canonical public inputs (≥ r)**: `Bn254Fr::from_bytes` reduces mod r, so `nullifier + r` would verify as the same field element while passing the byte-keyed `NullifierUsed`/`CommitmentUsed` checks (double financing). Malformed points (off-curve G1/G2, G2 outside the subgroup) trap in the host instead of returning `false`; well-formed wrong proofs return `false` → `Error::InvalidProof`.
- 2026-10-25: Circuit details: `commission_rate_bps` is bounded to 10 bits (`Num2Bits(10)`, 1000 < 2^10) before the `GreaterEqThan(10)`/`LessEqThan(10)` comparators so they are sound; `rem` is bounded by `Num2Bits(14)` + `LessThan(14)`; `odd` and `rem` are prover hints (`<--`) pinned by constraints. 11,716 constraints (9,000 non-linear), default circom optimization (`--O1`). NIFs are not range-checked (not required by §8.3).
- 2026-10-25: The Rust fixture lives at `contracts/shared/fixtures/groth16_fixture.rs` (generated by `scripts/vk-to-soroban.ts`, included with `include!` by the shared and cpcv_note tests) rather than `circuits/test/` (spec §6): it is Rust code consumed only by the contract crates. It holds three real proofs (fixed TEST keys; two agents, one odd total) so tests can mint several notes.
- 2026-10-25: Circuit tests use Node's built-in `node:test` (no extra dependency) with an independent JS re-implementation of the input encoding; each violated constraint is pinned to its source line via the witness calculator's assertion message.
- 2026-10-25: `cpcv_note` ids start at **1** (`count()` = ids minted); `list(start, limit)` returns notes with id ≥ `start` in id order (so `start` 0 and 1 both mean "from the first"; next page = last id + 1) and silently caps `limit` at 50.
- 2026-10-25: `cpcv_note` storage additions: persistent `AgentNotes(Address) → Vec<u32>` backs `notes_of`; `NullifierUsed`/`CommitmentUsed` store the id of the note that used them. OpenZeppelin's `Owner(id)`/`Balance(agent)` entries are extended to the 90-day persistent TTL at mint (OZ only extends them to 30 days on reads). `minted_at` = `pool.protocol_now()` at mint.
- 2026-10-25: `token_uri = base_uri + "/" + id` via OpenZeppelin's `Base::token_uri` with its metadata `base_uri` set to `base_uri + "/"` (unless it already ends with "/"); `base_uri` must be < 200 bytes (OZ limit including the separator). The raw `base_uri` is also kept in instance storage as listed in spec §7.2.
- 2026-10-25: `cpcv_note` extras beyond spec §7.2 (additive): view `attester_params() → { attester_ax, attester_ay, nullifier_secret_commitment }` so anyone can rebuild public inputs 6–8 from chain data (`lib/zk/public-signals.ts`); `mint` rejects `total_commission_cents == 0` with `InvalidAmount`; the constructor rejects a VK whose `ic` is not 10 points or non-canonical attester parameters (`InvalidProof`). `set_status` does not police transitions (the pool owns the line state machine).
- 2026-10-25: Soulbound: the OZ `NonFungibleToken` trait methods return `()`, so `transfer`/`transfer_from`/`approve`/`approve_for_all` fail via `panic_with_error!(Error::Soulbound)` (clients see contract error #17). OZ's standard `mint` event is emitted alongside `note_minted`.
- 2026-10-25: Costs (soroban-sdk 28 test budget): `groth16::verify` = 34,914,918 CPU instructions / 203 KB; `cpcv_note.mint` = 35.6M native, **36,677,412 with the optimized wasm** (23,268 bytes) and a native mock pool. Testnet limit (protocol 29, read 2026-10-25): 400M instructions and 40 MiB per transaction, so a mint uses ~9%. Uses `g1_mul`/`g1_add` per spec; `g1_msm` (protocol 26) would be cheaper if ever needed.
- 2026-10-25: `lib/zk` layout: `field`/`format`/`agent-field`/`public-signals` are browser-safe (no Node built-ins, no `Buffer`) for the registry's in-browser verification (`verify.ts` → `verifyNoteProof`); `poseidon`/`keys`/`attestation`/`prove`/`artifacts` are server-side without `server-only` (tsx scripts import them). `proveCpcv` keeps the stub signature; `proveCpcvWithKeys(agent, input, keys, onStep?, { salt? })` takes explicit keys for scripts and tests. Invalid input throws `CpcvInputError` (`status` 400, `code` INVALID_*), not `HttpError`: `lib/http` imports through the `@/` alias, which Vitest cannot resolve without a config, so `lib/zk` value imports are relative and Vitest runs without a `vitest.config.ts`.
- 2026-10-25: Artifact lookup is `process.cwd()`-relative (`zk/` for Next.js/Vitest/Vercel, `../apps/web/zk` for scripts, `ZK_ARTIFACTS_DIR` override); the Next.js candidate is statically scoped (`path.join(process.cwd(), "zk")`) and the script-only candidates carry `turbopackIgnore`, so `next build` traces exactly `apps/web/zk/**` into the route (checked in `route.js.nft.json`) instead of the whole project. Verified with a throwaway route handler under Next.js 16.4 `next dev` (Turbopack) and `next build` + `next start`: no `serverExternalPackages` needed; proofs 0.9 s cold / 0.37–0.46 s warm on an Apple-silicon laptop. Adding `outputFileTracingIncludes: { "/api/admin/cpcv": ["./zk/**"] }` (spec §8.6) remains a harmless belt-and-braces for the route owner.
- 2026-10-25: snarkjs keeps a cached multi-threaded curve (`globalThis.curve_bn128`) after proving/verifying: good for warm serverless instances; tsx scripts and tests call `releaseZkResources()` so the process can exit.
- 2026-10-25: **Full mint cost with the real pool** (`contracts/integration_tests`, optimized wasm of both contracts, cross-contract `protocol_now` + `open_line` included): 39,034,168 CPU instructions (9.8% of testnet's 400M per transaction), 3,089,911 memory bytes (7.4% of 40 MiB), 25 ledger entries (14 read, 11 written; limit 400), 6,076 write bytes (4.6% of 132,096), 744 event bytes (4.5% of 16,384); natively 36.1M (host functions only). Limits read with `stellar network settings --network testnet` (protocol 29). Estimated resource fee ≈ 3.6 XLM, almost all rent for the ~8 new persistent entries kept 90 days (SDK rent rate, an overestimate): fund the operator accordingly.

## Auth and database

- 2026-10-25: Initial migration `init` is generated from `schema.prisma` (spec §9.1) plus one additive column, `EmailCode.createdAt`, which drives the per-email resend cooldown and hourly cap from Postgres (works across serverless instances, unlike an in-memory limiter).
- 2026-10-25: `lib/db` creates the Prisma client lazily on first property access (a Proxy over the singleton), so importing it never reads env. Scripts import it through `@/lib/db` (verified with `tsx --tsconfig scripts/tsconfig.json`); they should run with `tsx --env-file=../apps/web/.env.local` (or call `process.loadEnvFile` before the first query) and end with `db.$disconnect()`.
- 2026-10-25: Prisma 7's `migrate dev` does not regenerate the client: run `pnpm --filter web db:generate` after creating a migration. `pnpm --filter web db:reset` = `prisma migrate reset --force`, for dev databases only (Prisma refuses to run it for an AI agent without the user's consent).
- 2026-10-25: PII encryption (`lib/crypto`): AES-256-GCM with a random 96-bit IV and 128-bit tag over UTF-8 JSON, stored as `iv ‖ tag ‖ ciphertext` bytes; key = `PII_ENCRYPTION_KEY` (64 hex chars). No key-version prefix: a single key for the hackathon, rotating it would mean re-encrypting rows.
- 2026-10-25: Email sign-in codes are stored as HMAC-SHA256(key = `SESSION_SECRET`, message = normalized email + code), i.e. "SHA-256 + SESSION_SECRET" as a proper keyed hash, bound to the address it was issued to. Compared in constant time.
- 2026-10-25: Vitest resolves the `@/` alias through Vite 8's `resolve.tsconfigPaths` (`apps/web/vitest.config.mts`); tests that touch the database mock `@/lib/db`, so `pnpm --filter web test` needs no Postgres.
- 2026-10-25: Sessions: iron-session cookie `advance_session` (httpOnly, SameSite=Lax, 7 days, `Secure` when `NODE_ENV=production`). `getSessionUser()` re-reads the user from Postgres, so deleted users (e.g. after a demo reset) read as signed out and role changes apply at once; `proxy.ts` only unseals the cookie (optimistic check, no database), and API routes always enforce with `requireAgent()`/`requireAdmin()`.
- 2026-10-25: The spec's "short pre-passkey session": a session started by an email code (`passkeyVerified = false`) stops being valid 24 h after sign-in; `signIn(user, { passkeyVerified: true })` (passkey registration or passkey login) gives the full 7 days. 24 h rather than minutes because the email code is also the fallback login and the only login seed agents have.
- 2026-10-25: `requireAdmin()` does not demand a passkey: the email code is a valid (fallback) login for admins too (§9.2). `requireAgent()` lets pre-passkey sessions through for onboarding, as the interface documents.
- 2026-10-25: `ADMIN_EMAILS` is the source of truth for the admin role: new users get their role at creation and existing users are re-synced on every email sign-in (added → promoted, removed → back to AGENT).
- 2026-10-25: Proxy redirects: signed-out visitors of `/agent/**` or `/admin/**` → `/login?next=<path>`; an AGENT on `/admin/**` → `/agent`; an ADMIN on `/agent/**` → `/admin` (admins have no agent account). `next` is only honoured for same-origin paths the role may open.
- 2026-10-25: Email codes: issuing a code supersedes the previous live one (one usable code per email). Limits: 5 attempts per code (each attempt is reserved atomically before comparing, so parallel guesses can't exceed it), 30 s resend cooldown and 5 codes per email per hour (Postgres), plus best-effort in-memory per-IP limits (20 starts and 50 verifies per 10 min per instance). Rate-limit errors are 429 `RATE_LIMITED` / `RESEND_COOLDOWN` / `TOO_MANY_ATTEMPTS`. A code whose email fails to send is deleted so the user can retry at once.
- 2026-10-25: Seed agents (`@demo.explorador.pt`) are never emailed. While `DEMO_MODE=true`, `POST /api/auth/email/start` returns their code in the response (`demoCode`, `delivery: "demo"`) so the presenter and judges can sign in as them; only for existing users on that domain (cap 30 codes/hour). With `DEMO_MODE` off they can't sign in by email.
- 2026-10-25: `/login` (email → code, minimal Tailwind; restyled later with the design system) shows a signed-in visitor "Continue / sign out and use another email" instead of redirecting: account switching works without other UI, and since that check reads the database, a stale cookie can never bounce between the proxy and the login page. After verify the browser does a full navigation to `redirectTo`. Passkey sign-in on this page is left for the agent-app / smart-accounts integration.
- 2026-10-25: The sign-in POST routes only accept `Content-Type: application/json` (415 `UNSUPPORTED_MEDIA_TYPE` otherwise). `parseBody` parses any body, so without this a cross-site `text/plain` form could post JSON and sign a victim into the attacker's account (login CSRF).

## Card (Lithic ASA)

- 2026-10-25: **Simulated card network while `LITHIC_API_KEY` is unset** (no key exists yet): `createAgentCard` issues `sim_card_…` cards (random last4); `POST /api/agent/card/simulate` builds an ASA request typed against the SDK's `CardAuthorizationApprovalRequestWebhookEvent` (USD cents, Visa, token `sim_txn_…`) and runs it through the same parser and pipeline as `POST /api/lithic/asa`, in-process: same decision, same `CardAuthorization` row, same `after()` draw; `via: "simulated"`. Reveal returns obviously fake details (`4000 0000 0000 <last4>`, CVV `000`). A simulated card keeps using the simulated network even after a key is added; `createAgentCard` replaces it with a Lithic card when called again with a key.
- 2026-10-25: Lithic facts that refine the spec (verified in `lithic@0.148.0` sources and docs.lithic.com): enrollment is `responderEndpoints.create({ type: "AUTH_STREAM_ACCESS", url })` + `authStreamEnrollment.retrieveSecret()` (returns `whsec_…`, created on first call; signed headers start appearing minutes later); simulate is `transactions.simulateAuthorization({ amount, descriptor, pan })` → `{ token }`, the same token the ASA request carries; ASA statuses are AUTHORIZATION, FINANCIAL_AUTHORIZATION, BALANCE_INQUIRY and CREDIT_/FINANCIAL_CREDIT_AUTHORIZATION (credit decisioning only); reversals never reach ASA; the response may echo `token`; Lithic waits up to 6 s, retries once on 5xx, declines on 4xx; sandbox writes are limited to 1/s (simulations, responder endpoints) and 2/s (cards); card-creation idempotency keys must be UUIDs.
- 2026-10-25: ASA signatures follow Standard Webhooks: base64 HMAC-SHA256 of `${webhook-id}.${webhook-timestamp}.${rawBody}` keyed with the base64-decoded secret (minus `whsec_`), `webhook-signature` = space-separated `v1,<sig>` list, 5-minute timestamp tolerance. Implemented with `node:crypto` and tested against the reference vector and the SDK's own verifier (`standardwebhooks` isn't a direct dependency, and the SDK verifier needs a client with an API key). As specced, unsigned requests are accepted only while `LITHIC_ASA_HMAC_SECRET` is unset; set it on every deployment with a Lithic key (card tokens are unguessable UUIDs and draws can only pay `card_settlement`, so the window is a griefing risk, not a theft risk).
- 2026-10-25: `card_enabled` from a live `agent_position` read decides CARD_PAUSED; `Agent.cardEnabledOnChain` (its DB mirror, written by the agent-tx/seed flows) decides only when the read fails, and is corrected from the live read in `after()`. The spec checks the DB flag alone, which would decline every purchase if a flow forgot to update it.
- 2026-10-25: Decision details the spec leaves open: unknown card → SUSPECTED_FRAUD for every status, nothing recorded (no agent to attach a row to); no live read and no cache → INSUFFICIENT_FUNDS; without live stats the position's own `borrowable_now` (the same min, computed on-chain) bounds credit; with a cached position, approved draws CONFIRMED after `cachedAt` also count as pending holds; zero-amount purchases and credits are approved and recorded with `chainStatus = CONFIRMED` and no tx (nothing to draw); balance inquiries are not recorded (`balance.amount = available` = spendable cents, 0 for a paused card). Declined rows keep the schema default `chainStatus = PENDING`: `chainStatus` is meaningful only for APPROVED rows, so consumers filter on `decision` (pending holds, failed-draw alerts, pollers).
- 2026-10-25: `Agent.cachedPosition` holds `jsonify(AgentPosition)` (bigints as decimal strings) and `cachedAt` is when that read *started*; it is written after every live read and after every draw, only if newer than what is stored.
- 2026-10-25: Draw lifecycle: `after()` claims the row atomically (PENDING → SUBMITTED, `attempts + 1`), calls `cardDraw(agent, cents × 100_000, sha256(lithic token))`, then CONFIRMED with split + tx hash or FAILED. At most 3 attempts in total. Contract error `DuplicateDraw` (#12) means an earlier attempt landed: the row becomes CONFIRMED, with the split recovered from indexed `card_draw` events when available. The status poll re-arms an approved draw still PENDING after 15 s (lost `after()`).
- 2026-10-25: Retry sweep (`retryDraws`, `/api/cron/retry-draws`): FAILED draws, plus PENDING/SUBMITTED older than 2 minutes, with fewer than 3 attempts, 5 per run, oldest first; SUBMITTED rows out of attempts become FAILED unless found in indexed events. One sweep at a time (`pg_try_advisory_xact_lock`); optional `agentId` scope. The route accepts an admin session or `Authorization: Bearer $CRON_SECRET` (new optional env var, what Vercel Cron sends); the admin page can also call `retryDraws()` directly (prefer `after()`: each retry is a testnet transaction).
- 2026-10-25: Simulate API: `amountEur` > 0, ≤ €50,000, at most 2 decimals; `merchant` 1–40 chars. Lithic mode reads our ASA row back by transaction token (waits up to 4 s); when Lithic declined without consulting us the decline is recorded with Lithic's `result` as `declineReason`; if Lithic approved without calling our responder the API returns 502 `ASA_NOT_REACHED` (enroll the URL). Lithic writes are spaced in-process (1.1 s for simulations, 0.55 s for cards) and a simulate waiting more than 4 s for its slot gets 429; the UI should still debounce.
- 2026-10-25: Card creation: `cards.create({ type: "VIRTUAL", memo: <agent user id>, card_program_token: "00000000-0000-0000-1000-000000000000" })` (sandbox Visa test BIN) with a deterministic UUID `Idempotency-Key` derived from the user id, so a retried onboarding gets the same card. `createAgentCard` returns the card already on the Agent row if any, and stores a new one on the row when the row exists; otherwise the caller stores it. Amounts stay USD cents treated as EUR 1:1 (spec): `simulate/authorize` is called without `billing_currency`.
- 2026-10-25: Local Lithic dev needs a public URL: run a tunnel (`cloudflared tunnel --url http://localhost:3000` or `ngrok http 3000`) and `pnpm lithic:enroll --url <https tunnel URL>`; the script prints the `LITHIC_ASA_HMAC_SECRET=` line (`--status`, `--disenroll` for housekeeping).
