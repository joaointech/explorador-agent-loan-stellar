# DECISIONS

Choices made where `spec.md` left a detail open, and every place the build deviates from
the spec, with the reason. The fixed decisions in spec §2 are unchanged.

## Toolchain and versions

| Item | Choice | Why |
|---|---|---|
| Soroban SDK | `soroban-sdk` 28.0.0 | Latest stable that the OpenZeppelin `stellar-*` 0.8 crates build against; exposes `crypto::bn254` (testnet is on protocol 29). |
| OpenZeppelin crates | `stellar-tokens`, `stellar-access`, `stellar-macros`, `stellar-contract-utils` 0.8.0 | Latest release compatible with sdk 28. |
| `soroban-fixed-point-math` | **Not used** | v1.5.0 pins soroban-sdk 25 and won't resolve next to sdk 28. `contracts/shared/src/math.rs` implements the same checked `mul_div_floor` / `mul_div_ceil` on i128. All products stay < 10^33, and overflow returns `MathOverflow`. |
| `@stellar/stellar-sdk` | pinned to 16.4.1 | `smart-account-kit` 0.8.0 depends on exactly this version. Two copies of the SDK break `instanceof` checks on XDR types. |
| Next.js | 16.4 (App Router, Turbopack) | Latest stable. Route protection lives in `apps/web/proxy.ts`, Next 16's replacement for `middleware.ts`. |
| Prisma | 7.10 with the `prisma-client` generator and `@prisma/adapter-pg` | Latest stable. The client is generated into `apps/web/lib/generated/` (git-ignored, generated on `postinstall`). The schema is applied with `prisma db push`; there are no migration files yet. |
| pnpm | 11, `allowBuilds` in `pnpm-workspace.yaml` | pnpm 11 blocks install scripts unless allowed. |

## Testnet rent surcharge (important for deploys)

Testnet's live Soroban state (~4.1 GB) is above its 4 GB target, so rent fees carry a
large multiplier. Uploading contract code costs about **200 XLM per KB of wasm**
(teurc ≈ 2,300 XLM, advance_pool ≈ 11,000 XLM). Consequences:

- **Fee bump.** The total fee exceeds the uint32 limit of a normal transaction fee (~429 XLM).
  `lib/stellar/client.ts → assembleSigned` falls back to a fee bump when that happens. The inner
  tx has fee 0 and carries the real `resourceFee` in its Soroban data; an outer int64 fee bump
  pays for it. The Stellar CLI does the same.
- **XLM top-up.** Friendbot gives 10,000 XLM per new account. `ensureXlm` in
  `lib/stellar/network.ts` funds throwaway accounts with Friendbot and `accountMerge`s them
  into the role account until the target balance is reached. Uploads are sized from the simulated
  fee, and `deployAll` keeps a 5,000 XLM float on each role.
- **Uploads are content-addressed.** `uploadWasm` skips code the network already has, so a
  redeploy / `demo:reset` only pays for instances and entries.
- **Shorter TTLs.** Spec §7 asks for ~30 days (instance) and ~60–90 days (persistent). The
  contracts extend instance and persistent entries to **10 days whenever they drop below 6 days**
  (`contracts/shared/src/ttl.rs`), because each extension pays the surcharged rent. New entries
  start at the network minimum. `teurc` was uploaded earlier with 30-day instance constants and
  keeps them (re-uploading it only to change that would cost ~2,300 XLM). For a long-running
  deployment, run `pnpm demo:reset` (or an extend-TTL job) at least every week or two.

## Contracts

- **Error codes.** The 18 spec errors keep their order (1–18). Extra codes 19–27 are
  `MathOverflow`, `DemoModeDisabled`, `InvalidParams`, `ClockAdvanceTooLarge` (> 400 days in one
  call), `FaucetLimitExceeded`, `InsufficientBalance`, `ExceedsMaximum` (vault and fee limits),
  `PoolNotSet` and `NonCanonicalField` (a public input ≥ the BN254 scalar field).
- **`open_line` takes the note terms as arguments** (`note_id, agent, agent_commission, escritura_day`)
  instead of reading them back from `cpcv_note`. The call happens inside `cpcv_note.mint`, and
  Soroban forbids re-entering the note contract (note → pool → note). Only the registered note
  contract can call it.
- **Note ids start at 1.** `token_uri(id) = base_uri + "/" + id`, with base_uri `${APP_URL}/api/registry`
  (served by `/api/registry/[id]/metadata`). That is the SEP-50 metadata JSON with public fields only.
- **`settle` auth.** The pool requires `operator` auth, plus `treasury` auth only when treasury ≠
  operator. One key holding both roles can't `require_auth` twice in the same call
  (`Error(Auth, InvalidAction)`).
- **`AgentPosition.lines`** lists only active lines. Settled and cancelled lines remain readable via `line(id)`.
- **Settlement shortfall.** If a note's debt exceeds the agent's half, the whole half goes to the
  debt, the remainder becomes carried debt, and the grace deadline is set if none exists.
- **Partial repayment** of carried debt removes scaled debt rounded down, so any dust stays in the
  pool (it favours investors). Interest is repaid before principal, and principal is informational only.
- **Write-off order:** junior, then senior. If both are exhausted, the fee reserve covers the rest.
  This can't happen under the 10× leverage cap.
- **Extra event `blocked_set`** for `set_blocked`, so the indexer can show it.
- **Stats definitions** (where the spec only names them):
  - `utilization = total_debt / (senior + junior)`
  - `leverage_x100 = total_debt × 100 / junior`
  - share price uses the SEP-56 virtual offset: `(assets + 1) × 10^18 / (supply + 1)`
- **Groth16.** G2 points are passed in the order Soroban's `G2Affine` expects. `contracts/shared/src/groth16.rs`
  verifies the committed snarkjs fixture in a unit test, as §8.5 requires. Tests also cover a
  tampered input and a tampered proof.

## Zero-knowledge circuit

- **`property_hash` is one `Poseidon(len, c0 … c7)` call.** Poseidon's arity limit is 16 inputs and
  circomlib / circomlibjs both support 9, so the spec's two-call fallback ("if arity requires") isn't
  needed. TS (`packages/zk/src/hash.ts`) and the server use the same single call. It stays off-chain only.
- **Range checks.** Sale price, totals and the agent half use 64 bits; days use 32 bits. NIFs use
  30 bits (9 digits < 10^9 < 2^30), and the commission rate uses 16 bits, then `100 ≤ rate ≤ 1000` bps.
- **Normalized addresses** are limited to 248 UTF-8 bytes (8 × 31-byte chunks). Longer addresses are
  rejected in validation.
- **Trusted setup.** `circuits/build.sh` runs a local Powers of Tau (2^15) with random entropy. The
  zkey, the wasm and both verification keys are committed. **Re-running `circuits:build` produces
  a new key and requires a redeploy** (`pnpm deploy:testnet` / `pnpm demo:reset`), because `cpcv_note`
  stores the verification key at construction.
- Circuit tests (`circuits/test/circuit.test.ts`) use `snarkjs.wtns.calculate`. Each negative case
  re-signs the tampered record, so the signature check isn't what makes it fail; only the targeted
  constraint is violated.

## Accounts, auth and signing

- **Smart accounts** are the OpenZeppelin smart-account contracts that already exist on testnet
  (wasm `1b5f4534…`, WebAuthn verifier `CC7EKIHQ…`, Ed25519 verifier `CAAVTMCB…`). They can be
  overridden with env vars. Each agent account is deployed by `sponsor` with a single
  `External(verifier, keyData)` signer and salt `sha256(keyData)`, so deployment is idempotent per key.
  - Passkey agents: `keyData = P-256 public key (65 bytes) ‖ credentialId`.
  - Seed agents: `keyData` = 32-byte Ed25519 public key. The server holds the secret
    (`signerKind = "demo-ed25519"`), as §11.2 allows.
- **One passkey for login and signing.** The server creates the passkey with `@simplewebauthn/server`
  (not with `smart-account-kit`). The COSE key is converted to the 65-byte public key. Auth entries
  are signed in the browser (`lib/client/passkey.ts`) with a WebAuthn `get` whose challenge is the
  entry's auth digest (`computeEntryAuthDigest` from the kit). The DER signature is converted to
  compact low-S form and packed with the kit helpers.
- **Agent transactions** (`enable_card`, `disable_card`, `withdraw_balance`):
  - `prepare` builds the call with `sponsor` as source and returns the envelope. For demo agents
    the server signs the entries itself (`serverSigned: true`).
  - `submit` checks the contract, function and agent argument, rebuilds the call server-side, takes
    only the signed auth entries and submits sponsored.
- **Email login for seed agents and admins.** The spec says the email code is a fallback login.
  - Seed agents can't hold a passkey (it would be bound to one browser), so the code gives them a
    full session.
  - Admins also get a full session from the code, so the demo works on any machine.
  - Other agents must register a passkey before reaching `/agent`. Until then the session is
    "pre-passkey", and `proxy.ts` sends them to `/login`.
- **`/login` page.** The spec lists the agent and admin entry points; a single sign-in page serves both.
- **Operator transactions** are serialized with `pg_advisory_xact_lock` (spec §9.3). The lock call is
  cast to text, because Prisma's pg adapter can't decode `void`.

## Card (Lithic) and the ASA responder

- **No Lithic key → local simulation.** Without `LITHIC_API_KEY`, "Simulate purchase" runs the same
  `decideAuthorization` used by `/api/lithic/asa` in-process, then `after(processDraw)`. The approve /
  decline logic and the on-chain draw are identical; only the Lithic round trip is skipped. With a
  key, the server calls Lithic's `simulateAuthorization` and waits for the ASA row.
- **Simulate debounce.** At most one simulated purchase per user per ~1 s (`429 SLOW_DOWN`), to stop
  double-clicks from creating two Lithic authorizations.
- **Declined authorizations** are stored with `chainStatus = CONFIRMED` (nothing to do on-chain).
- **Card creation is lazy and never blocks onboarding.** If Lithic is down, the card is created on the
  next overview load.
- **`lithic:enroll`** creates an `AUTH_STREAM_ACCESS` responder endpoint for `${APP_URL}/api/lithic/asa`
  (or `--url`) and writes `LITHIC_ASA_HMAC_SECRET` to `.env.local`.

## Indexer, API and data

- **Lazy indexing.** Besides `pnpm indexer` (5 s loop) and the cron routes, read routes call
  `syncIfStale()`, which runs a sync plus a pool snapshot at most every 10 s (snapshots at most once a
  minute). This makes Vercel Hobby's once-a-day cron limit harmless (`apps/web/vercel.json`).
  `CRON_SECRET` protects `/api/cron/*`.
- **Extra routes** beyond §9.7:
  - `/api/auth/me` and `/api/auth/logout`
  - `/api/registry/[id]/metadata` (SEP-50 token URI)
  - `/api/investor/preview` (deposit / withdraw previews)
  - `/api/stellar/config`
  - `/api/agent/card/reveal` (sandbox PAN)
  - `/api/admin/agents` and `/api/admin/agents/[id]/write-off`
  - `/api/cron/sync` and `/api/cron/retry-draws`
- **Faucet.** `/api/faucet/teurc` sends 10,000 tEURC with `sponsor` as source, so an investor whose
  Freighter account has no XLM yet still gets tokens. The Freighter-signed `teurc.faucet` path is also
  available through `investor/tx/prepare`.
- **`.env.local` lives in `apps/web/`**. Next.js reads it there, and scripts load it via
  `lib/ops/load-env.ts`.
- **Root scripts** (`scripts/*.ts`) run with `tsx --tsconfig apps/web/tsconfig.json` and import only
  `apps/web/lib/**`, so all dependencies resolve from the web app.
- **`packages/zk` uses extensionless imports.** Turbopack doesn't map `./x.js` to `./x.ts` inside
  workspace packages.

## Tests

- `pnpm e2e` runs in its own database, `<db>_e2e`, created or synced with `prisma db push`. Each run
  deploys fresh contracts, and note ids restart at 1, so sharing the demo database would collide with
  demo rows and switch the active deployment under a running dev server. The script restores
  `deployments/testnet.json` afterwards, and it deletes only the e2e users it created.
- The ASA tests (`apps/web/tests/asa.test.ts`) mock the on-chain reads and use the real local database.
